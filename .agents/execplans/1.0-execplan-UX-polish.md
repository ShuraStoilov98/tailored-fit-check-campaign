# 1.0 Exec Plan — UX Polish

## Project

Tailored Fit Check Campaign App

## Objective

Refactor the current mock Fit Check web app so it feels like a premium Tailored experience, not a generic form-based prototype.

The current version is functionally useful but visually too basic. This pass should make the experience feel connected to the Tailored app: elegant, mobile-first, visual, confident, and lightweight.

## Core Campaign Promise

```text
Scan → snap your outfit → get an instant Fit Check
```

The product experience should communicate:

```text
A 30-second personal stylist check.
No app needed.
Then continue in Tailored for daily Fit Checks.
```

## Important Context

This is a marketing campaign web app, not the main Tailored app.

It will be used for:

* London conference activations
* London street activations
* QR code campaigns
* Instagram / TikTok / LinkedIn / Pinterest organic experiments
* Founder-led social media content

The user may be standing in public, scanning a QR code from Simona’s portable display. The experience must be fast, beautiful, and immediately understandable.

## Non-Negotiables

* Mobile-first.
* No login.
* No Firebase Auth.
* No wardrobe setup.
* No profile creation.
* No app download required before value is delivered.
* No storing uploaded photos.
* No body criticism.
* No “hot or not” energy.
* No generic HTML form look.
* No visible back navigation in the UI.
* Result should appear on a separate result page, not beneath the capture form.
* Keep the stack simple: FastAPI + static HTML/CSS/JS.
* Do not add React, Vite, Tailwind, or another frontend framework in this pass.

## Brand Direction

The web app should feel like a sibling of the Tailored mobile app.

Visual cues:

* Soft lavender / off-white background.
* Warm white rounded cards.
* Dark charcoal primary buttons.
* Elegant large spacing.
* Large rounded image cards.
* Minimal copy.
* Playfair Display for major headings and premium labels.
* Clean sans serif for body and utility text.
* Tailored logo mark visible at the top.

## Logo

Expected asset path:

```text
static/assets/tailored-logo.svg
```

If this asset exists, use it in the UI.

If it does not exist, implement a graceful fallback:

* show the word `Tailored`
* or reserve the logo area without breaking layout

Do not hard fail if the logo file is missing.

## Suggested Fonts

Use:

* `Playfair Display` for headings, large score numbers, premium labels
* `Inter` or system sans-serif for body, chips, buttons, utility text

A Google Fonts import is acceptable for this v1.

# Required UX Flow

## Screen 1 — Capture Page

Route:

```text
/
```

Purpose:

Get the user to upload or take an outfit photo with minimal friction.

### Required layout

Top:

* Tailored logo mark
* small eyebrow text:

```text
TAILORED DAILY FIT CHECK
```

Hero heading:

```text
Get your free AI Fit Check
```

Subcopy:

```text
Snap your outfit. Get an instant verdict.
```

Upload card:

* Large rounded warm-white card.
* Should feel tappable and app-like.
* Should not look like a default browser file input.
* Use hidden file input with a custom visual trigger.
* Support camera/gallery through native mobile file behaviour.

Upload card copy:

```text
Take or upload a photo
```

Occasion selector:

* Replace dropdown with quick tap chips.
* Options:

  * Work
  * Conference
  * Date
  * Dinner
  * Casual
  * Other

Primary CTA:

```text
Get my Fit Check
```

### Capture page acceptance criteria

* No visible dropdown for occasion.
* No default-looking file input.
* Looks good on iPhone-size viewport.
* User can still upload/take a photo.
* Selected occasion chip has clear visual selected state.
* CTA is disabled or gives friendly error until image is selected.
* Campaign parameters are preserved from URL.

## Screen 2 — Processing State

Purpose:

Make the wait feel polished and intentional.

After user taps `Get my Fit Check`, show a full-screen or large-card processing state.

Required copy:

```text
Checking your fit...
```

Subcopy:

```text
Looking at style, colour, and overall polish
```

Use a simple premium loading indicator.

No long text.

Acceptance criteria:

* User clearly understands something is happening.
* No raw spinner-only blank state.
* No technical loading language.
* Works even when mock API returns quickly.

---

## Screen 3 — Result Page

Route:

```text
/result
```

Purpose:

Deliver the “wow” moment.

The result must be visual-first and concise.

### Routing / state

After successful mock API response:

1. Store uploaded image preview and result data in `sessionStorage`.
2. Navigate to `/result`.
3. `/result` reads from `sessionStorage`.
4. If no result data exists, redirect back to `/`.

This keeps the app simple while making result feel like a real separate screen.

### Required sections

#### 1. Hero image card

At top of result page:

* Show uploaded outfit photo in a large rounded image card.
* Add subtle dark gradient overlay.
* Add short look label over the image.

Example look labels:

* `Clean casual look`
* `Conference-ready base`
* `Polished work look`
* `Bold everyday fit`

For mock response, derive from available mock data or use a sensible default.

#### 2. Overall score

Show:

* Label: `Overall score`
* Score on right: `4/5`
* Horizontal progress bar beneath

This should visually echo the current Tailored app Fit Check screen.

#### 3. Sub-scores

Show three compact score visuals:

* Fit
* Style
* Colour

Suggested mock values:

* Fit: 4
* Style: 3
* Colour: 4

Can be circles, pills, or compact cards. Keep it visual and mobile-friendly.

Avoid using the phrase `Body fit` for now. Use `Fit`.

#### 4. Suggested improvements

Show exactly three short suggestions.

Use numbered cards or pills.

Example:

```text
1. Add one structured layer for a more polished finish.
2. Cleaner shoes would sharpen the look.
3. One subtle accessory would complete the outfit.
```

Keep each improvement short. No paragraphs.

#### 5. CTA block

Primary CTA:

```text
Get daily fit checks in Tailored
```

Secondary CTA:

```text
Join the early community
```

Tertiary text link:

```text
Try another fit check
```

The primary app CTA should use `APP_STORE_CTA_URL` from config if already available in the frontend. If not wired yet, keep current placeholder behaviour but do not break the layout.

### Result page acceptance criteria

* Result is not rendered under the form.
* Result appears at `/result`.
* Result is visually led by the uploaded image.
* Text is compact.
* Suggestions are short.
* No long “What works” paragraphs.
* The page feels similar to the Tailored app screenshots.
* There is no visible back button.
* User has clear next actions.

# Content and Tone Rules

Feedback should feel like a premium stylist.

Do:

* “The palette feels cohesive.”
* “A cleaner shoe shape would sharpen the look.”
* “One structured layer would make this feel more intentional.”
* “This works well for casual work; one polished detail would elevate it.”

Do not:

* “This is unflattering.”
* “Your body shape does not suit this.”
* “You look short.”
* “This outfit is bad.”
* “Hot / not.”
* “Body fit.”

Avoid:

* harsh judgement
* body comments
* long paragraphs
* overly technical fashion language
* generic AI tone

# Definition of Done

This pass is done when the local mock experience feels credible enough to show as a Tailored-branded campaign prototype.

It does not need real AI yet.

It does need to feel visually polished enough that a user scanning a QR code in public would not immediately think:

```text
This is a rough dev prototype.
```
