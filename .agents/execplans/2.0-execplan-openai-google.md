# 2.0 Exec Plan — OpenAI Vision + Lightweight Google Logging

## Project

Tailored Fit Check Campaign App

## Objective

Replace the current mock Fit Check response with a real OpenAI vision-powered Fit Check, and add lightweight Google Sheet logging through a simple Google Apps Script webhook.

This pass should make the campaign experience truly useful while keeping the architecture simple and safe.

## Current State

The app already has:

* FastAPI backend
* Static mobile-first frontend
* Upload/take photo flow
* Occasion chips
* Processing state
* Separate `/result` page
* Session storage result handoff
* Mock `/api/fit-check` response
* Railway deployment
* Custom domain: `fitcheck.tailored-to-you.com`
* Short.io campaign links planned via `go.tailored-to-you.com`

## Goal for This Pass

When a user uploads an outfit photo:

```text
POST /api/fit-check
→ validate image
→ call OpenAI vision
→ receive structured Fit Check JSON
→ return same schema to frontend
→ log lightweight event to Google Sheet webhook
→ show result page
```

Also add lightweight logging events:

```text
page_view
photo_selected
fit_check_started
fit_check_completed
app_cta_clicked
email_submitted
error
```

For this pass, Google logging can be best-effort. Logging failure must not break the user experience.

# Required Response Schema

The backend must return the same shape expected by the current result page:

```json
{
  "verdict_label": "Strong base",
  "one_line_verdict": "Clean foundation with one easy tweak.",
  "overall_score": 4,
  "fit_score": 4,
  "style_score": 3,
  "colour_score": 4,
  "what_works": [
    "Balanced base",
    "Palette feels cohesive"
  ],
  "improvements": [
    "Add one sharper finishing touch",
    "Choose cleaner shoe lines",
    "Use one subtle accessory"
  ],
  "occasion_fit": "Works well for dinner.",
  "tailored_tip": "Small styling changes can make the outfit feel more intentional."
}
```

## Field Rules

### `verdict_label`

Short label, max 4 words.

Examples:

* `Strong base`
* `Polished`
* `Almost there`
* `Easy upgrade`
* `Confident casual`

### `one_line_verdict`

One concise sentence.

### Scores

All scores should be integers from 1 to 5:

```text
overall_score
fit_score
style_score
colour_score
```

Do not use 0 or decimals.

### `what_works`

Exactly 2 bullets.

Each bullet should be short:

* 3 to 8 words ideally
* no full paragraph

### `improvements`

Exactly 3 bullets.

Each bullet should be short, actionable, and non-judgemental.

### `occasion_fit`

One short phrase/sentence based on selected occasion.

### `tailored_tip`

One short habit-oriented tip.

## Desired Backend Shape

`app/main.py` should stay thin.

Suggested flow:

```python
@app.post("/api/fit-check", response_model=FitCheckResponse)
async def fit_check(...):
    validate image
    log fit_check_started
    result = await generate_fit_check(...)
    log fit_check_completed
    return result
```

OpenAI-specific logic should live in:

```text
app/fit_check.py
```

Prompt text should live in:

```text
app/prompts.py
```

Event logging should live in:

```text
app/event_logging.py
```

## Image Handling

* Read uploaded file bytes.
* Validate type and size before OpenAI call.
* Convert to base64 data URL.
* Send image to OpenAI from backend only.
* Do not write image to disk.
* Do not store image in logs.
* Do not include image bytes in error logs.

## Suggested OpenAI Implementation

Use the OpenAI Python SDK already in `requirements.txt`.

Use environment:

```text
OPENAI_MODEL
OPENAI_API_KEY
```

Use a structured-output approach where possible. If SDK/version makes strict schema awkward, fallback to JSON mode and validate with Pydantic.

The returned object must be parsed into `FitCheckResponse`.

## OpenAI Failure Handling

If OpenAI call fails:

* return HTTP 502 or 500 with a friendly frontend-safe message
* log event type `error`
* do not leak API/provider details to the frontend

Frontend should display:

```text
We couldn’t complete your Fit Check just now. Please try again in a moment.
```

# Prompt Requirements

The AI stylist must:

* Focus on outfit, not body.
* Be constructive.
* Be concise.
* Avoid attractiveness ratings.
* Avoid body-shape comments.
* Avoid gender assumptions unless obvious from clothing/context.
* Give useful styling guidance.
* Respect occasion if provided.
* Return only valid JSON matching schema.

## Prompt Style

Brand voice:

* premium
* concise
* kind
* practical
* fashion-literate but not jargon-heavy

Do not say:

* “This is unflattering”
* “Your body shape”
* “You look short”
* “This outfit is bad”
* “Hot”
* “Sexy”
* “Body fit”

Prefer:

* “The proportions feel balanced”
* “A cleaner shoe shape would sharpen the look”
* “One structured layer would make it feel more intentional”
* “The palette feels cohesive”

# Google Sheet Logging

## Use Apps Script Webhook

Do not implement full Google Sheets API/service account in this pass.

Use a Google Apps Script Web App with `doPost(e)` that appends rows to a Google Sheet.

Backend sends JSON to:

```text
GOOGLE_SHEET_WEBHOOK_URL
```

If blank, event logging should no-op.

## Events to Log

Log these events from backend where possible:

```text
fit_check_started
fit_check_completed
error
```

Frontend can also call `/api/event` for:

```text
page_view
photo_selected
app_cta_clicked
email_submitted
```

For v2.0, it is acceptable to implement backend logging first and frontend logging if straightforward.

## Event Payload

Each event should include:

```json
{
  "timestamp": "server generated ISO timestamp",
  "event_type": "fit_check_completed",
  "campaign_id": "fit_test_a",
  "source": "qr",
  "slug": "fit-test-a",
  "occasion": "Conference",
  "environment": "production",
  "success": true,
  "error_message": ""
}
```

Do not send image data.

Do not send the uploaded photo.

Do not send full OpenAI raw response unless explicitly needed. Prefer concise structured fields only.

# Apps Script Webhook Shape

Create Apps Script attached to the Google Sheet.

Use a `doPost(e)` function that:

1. Parses JSON.
2. Opens active spreadsheet.
3. Selects `events` sheet.
4. Appends a row.
5. Returns JSON response.

Deploy as Web App:

* Execute as: Me
* Who has access: Anyone

Use the Web App URL as:

```text
GOOGLE_SHEET_WEBHOOK_URL
```

Security note:
For v2.0 this is acceptable for speed. Later add a shared secret header or token.
